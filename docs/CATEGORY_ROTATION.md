# Ротация изображений популярных категорий

## Назначение

На главной отображаются 9 популярных категорий и до 6 изображений популярных
товаров в каждой. Изображения меняются примерно раз в час, при этом
посещение главной не создаёт запросов к базе данных.

## Поток данных

1. `services/HomePopularCategories.ts` одним SQL-запросом:
   - агрегирует статистику за 30 дней;
   - выбирает 9 категорий с наибольшим числом просмотров;
   - выбирает до 24 товаров-кандидатов с изображениями для каждой категории.
2. Пул кандидатов хранится в Next.js Data Cache 6 часов.
3. Для текущего часового интервала сервис детерминированно выбирает
   6 изображений из пула.
4. `app/page.tsx` отдаётся через ISR с `revalidate = 3600`.

Обычный посетитель получает готовые HTML/RSC из Full Route Cache. Тяжёлая
агрегация выполняется не чаще четырёх раз в сутки на один общий Data Cache.

## Почему выбор детерминированный

Порядок кандидатов вычисляется из:

```text
часовой интервал + handle категории + id товара
```

Поэтому разные процессы приложения выбирают одинаковые изображения, результат
можно кешировать, а PostgreSQL не выполняет дорогой `ORDER BY RANDOM()`.

## Рейтинг

Категории ранжируются по просмотрам. Товары внутри категории используют вес:

```text
view × 1 + click × 3 + add_to_cart × 5
```

Если свежей статистики нет, категории сортируются по количеству активных
товаров, а товары — по дате создания. Товар без изображения не попадает в пул.

## Кеширование

| Уровень | Интервал | Назначение |
|---|---:|---|
| Data Cache | 6 часов | Пул категорий и товаров-кандидатов |
| Full Route Cache / ISR | 1 час | Готовая главная страница |
| API/CDN | 1 час | Совместимый диагностический endpoint |

Endpoint `/api/categories/popular-images` сохранён для совместимости и
диагностики. Главная вызывает сервис напрямую, без HTTP-запроса к самой себе.

## Конфигурация

Все прикладные параметры находятся в `config/category-rotation.ts`:

- `categoryLimit`;
- `imagesPerCategory`;
- `candidatePoolSize`;
- `statisticsPeriodDays`;
- `rotationSeconds`;
- `rankingCacheSeconds`;
- `weights`.

Значение `revalidate` в route-файлах записано литералом `3600`, поскольку
Next.js 14 требует статически анализируемый route segment config. При изменении
`rotationSeconds` эти два литерала также нужно обновить.

## Индексы

Миграция API добавляет индексы:

```text
product_statistics(created_at, product_id, type)
products(enabled, category_id)
product_images(product_id, position)
```

Они соответствуют фильтрации статистики, выбору активных товаров по категориям
и поиску первого изображения.

## Отказоустойчивость

- При ошибке БД главная использует статические категории с placeholder.
- При ISR-регенерации Next.js продолжает отдавать предыдущую страницу.
- Если в категории меньше 6 подходящих товаров, сетка дополняется placeholder.
- Абсолютные URL не из настроенного `AWS_IMAGE_DOMAIN` не попадают в обложку.

## Проверка

```bash
cd store
npm run build
curl -I http://localhost:3010/
curl -I http://localhost:3010/api/categories/popular-images
```

В production build главная должна иметь ISR-интервал 1 час, а API —
`Cache-Control` с `s-maxage=3600`.
